# ONSURE 범용 검증 플랫폼 v1

## 1. 제품 정의

ONSURE은 특정 프로젝트 전용 시험기가 아니다. 일반 사용자·개발자·제품팀이 AI로 만든 프로그램과 일반 프로그램을 검증하고, 오류·보안·정책·구조·실행 문제를 찾아 근본원인분석을 수행하며, 검증 보고서·개선안·패치·재검증 증거까지 제공하는 독립 상용 검증 플랫폼이다.

```text
제품 성격       독립 상용 소프트웨어 검증 플랫폼
핵심 실행 방식  독립 실행
검증 범위       AI 응용프로그램 + 일반 소프트웨어
기준 검증 대상  ONSURE 자체 + 중립 Java/Python/Node 프로그램
대상 관계       EXTERNAL_VALIDATION_TARGET
향후 내장 형태  ONSURE_AGENT 또는 ONSURE_VALIDATION_MODULE
제품 원칙       ONSURE 독립 제품선 유지
```

## 2. 제품 사용자와 사용 시나리오

### 2.1 일반 사용자

- AI 코딩 도구로 만든 프로그램이 실제로 안전하고 정상적인지 확인한다.
- 실행은 되지만 누락된 예외·권한·보안·복구 경로를 탐지한다.
- 무엇이 잘못됐고 어떻게 고쳐야 하는지 이해 가능한 보고서를 받는다.
- 허용된 범위에서 자동 개선 후 동일 조건으로 재검증한다.

### 2.2 개발자와 제품팀

- 요구사항·설계·코드·테스트·보안·운영 계약 간 불일치를 탐지한다.
- 시험 데이터·실행 하네스·판정 오라클 기반으로 반복 실패를 재현한다.
- 소스·정책·의존성·산출물·검증 영수증 계보를 고정한다.
- 회귀 잠금과 독립 재검증으로 수정 안전성을 입증한다.

### 2.3 기업 검증 조직

- 여러 프로젝트를 검증 대상 등록소에 등록해 동일 검증 체계를 적용한다.
- 팀·제품별 정책 프로필과 승인 경계를 적용한다.
- 감사 가능한 발견사항·근본원인분석·영수증·최종 보고서를 보존한다.
- 사내망·로컬·서버·내장 모듈 배포 방식을 선택한다.

## 3. 범용 검증 엔진

```text
검증 대상 등록
→ 대상 어댑터 / 입력 접수
→ 변경 불가 소스·산출물 잠금
→ 요구사항·정책·아키텍처 재구성
→ 정적 검증
→ 실행·종단간 하네스
→ 보안·개인정보·공급망 검증
→ 실패 유형 등록소
→ 근본원인분석 엔진
→ 시험 데이터 합성·등록
→ 판정 오라클 평가
→ 개선 계획 / 승인된 패치 빌드
→ 회귀 잠금
→ 독립 재검증
→ 검증 보고서
→ 영수증 대장 / 최종 판정
```

### 3.1 검증 대상 등록

모든 검증 대상은 대상 등록소에 등록한다. 대상은 저장소, 패키지, 실행 파일, 실행 환경, 정책 문서, 데이터 계약을 포함할 수 있다.

대상 어댑터는 대상의 언어·프레임워크·빌드·실행 특성을 ONSURE 표준 증적 계약으로 변환한다. 어댑터는 검증 정책이나 최종 판정을 바꿀 권한이 없다.

### 3.2 증적 그래프

ONSURE은 다음 관계를 하나의 증적 그래프로 구성한다.

```text
요구사항 → 설계 → 코드 → 설정 → 의존성
→ 빌드 산출물 → 실행 동작 → 시험 증적
→ 발견사항 → 근본원인분석 → 패치 → 회귀검증 → 최종 판정
```

모든 주장에는 소스 위치, 해시, 권위, 시각, 정책, 실행 ID가 결속되어야 한다.

### 3.3 정적 검증

- 언어·프레임워크별 구문·타입·품질·취약점 검사
- 인증·인가·입력 검증·비밀정보·개인정보 검사
- AI 프로그램의 프롬프트 주입·도구 오용·데이터 유출 검사
- 설정·배포·의존성·라이선스·SBOM·출처 증명 검사
- 요구사항·설계·코드·테스트 간 누락과 충돌 검사

### 3.4 실행 하네스

- 정상·예외·장애·복구·동시성·대용량 시나리오 실행
- 외부 서비스 실패·시간 초과·부분 성공·재시도·중복 실행 검증
- AI 응답 변동·도구 오용·권한 경계·환각·근거 누락 검증
- 동일한 잠금 입력으로 반복 실행해 재현성 비교

### 3.5 실패 유형과 근본원인분석

실패 유형 등록소는 증상만 저장하지 않는다.

```text
실패 유형
→ 촉발 조건 / 선행 조건
→ 관찰 증상
→ 위반 계약
→ 영향 범위
→ 근본원인
→ 최소 수정
→ 지속 가능한 수정
→ 필요한 시험 데이터 / 오라클 / 회귀검증
```

동일 원인의 변형 실패를 묶고, 수정 후 재발 여부를 회귀 잠금으로 추적한다.

### 3.6 시험 데이터·실행 하네스·판정 오라클

- 시험 데이터: 정상·경계·적대·장애 입력과 환경 상태
- 실행 하네스: 대상 실행·격리·관찰·복구를 수행하는 실행체
- 판정 오라클: 기대 결과·허용 오차·정책·증거를 이용한 판정기

시험 데이터와 오라클은 대상 제품의 주장만 신뢰하지 않고 ONSURE이 독립 계산할 수 있는 형태로 저장한다.

### 3.7 검증 영수증과 회귀 잠금

검증 영수증은 소스·정책·대상·시험 데이터·하네스·오라클·발견사항·패치·결과를 서명된 증거 체인으로 묶는다.

회귀 잠금은 다음을 고정한다.

- 검증 대상 변경 불가 소스와 산출물
- 실행 환경과 의존성·도구 모음
- 시험 데이터 집합과 오라클 버전
- 정책 프로필
- 발견사항·근본원인·패치 연결
- 반복 실행 결과와 허용 차이

### 3.8 보고서와 개선·재검증

ONSURE의 최종 산출물은 단순 오류 목록이 아니다.

- 경영진·일반 사용자용 위험 요약
- 개발자용 재현 절차와 기술 근본원인분석
- 우선순위·영향도·수정 난이도 기반 개선 계획
- 자동 수정 가능 범위와 승인 필요 범위
- 패치 전후 결과 비교
- 남은 위험과 배포 가능 여부
- 영수증·증적 링크가 포함된 최종 검증 보고서

## 4. 외부 검증 자산 흡수 원칙

외부 프로젝트에서 확인한 다음 구조는 출처와 권리를 확인한 뒤 ONSURE 검증 엔진의
설계 재료로 일반화할 수 있다.

- 근본원인분석
- 실패 유형
- 시험 데이터
- 실행 하네스
- 판정 오라클
- 검증 영수증
- 회귀 잠금

흡수 원칙은 다음과 같다.

1. 개념·계약·실패 패턴은 범용화한다.
2. 외부 제품의 경로·이름·에이전트·실행 환경을 ONSURE 필수 의존성으로 만들지 않는다.
3. 제품 전용 시험 데이터는 선택형 대상 팩으로 분리한다.
4. 범용 엔진 계약과 대상 어댑터 계약을 분리한다.
5. 검증 대상의 자체 판정을 ONSURE 판정으로 그대로 승격하지 않는다.

## 5. 독립 기준 검증 대상

ONSURE은 특정 외부 제품 연결 없이 독립 제품 기준선을 완성한다. 범용성은 서로 다른
언어와 실행 모델을 가진 중립 대상 집합으로 입증한다.

```text
ONSURE 자체 Java/Maven 검증
→ 중립 Python 프로그램 검증
→ 중립 Node/TypeScript 프로그램 검증
→ 선택형 OpenAPI·PostgreSQL 검증
→ 동일한 범용 Profile·하네스·오라클·영수증·보고서
```

특정 회사·제품·모노레포의 연결은 ONSURE 완성 조건이나 필수 실행 환경이 아니다.

## 6. 장기 이식 구조

장기적으로 검증 대상 환경에 다음 중 하나를 선택 이식할 수 있다.

### 6.1 ONSURE 에이전트

- 대상 환경의 상태·로그·영수증 수집
- ONSURE 독립 엔진으로 이식 가능한 증적 전달
- 로컬 사전 검사와 즉시 차단 수행

### 6.2 ONSURE 검증 모듈

- 대상 실행 환경에서 일부 시험 데이터·정책·영수증 검증 수행
- 독립 검증·감사 또는 외부 ONSURE에서 결과 재계산 가능
- 대상 내부 결과를 이식 가능한 영수증으로 내보냄

이식 후에도 다음은 유지한다.

- ONSURE 별도 제품·저장소·배포판
- 외부 제품 연결 없이 실행 가능한 독립 핵심 체계
- 대상 내부 판정과 ONSURE 공식 판정의 권한 분리
- 독립 재검증 가능한 증적과 영수증
- 대상 Adapter 제거·장애가 ONSURE 핵심 체계를 중단시키지 않는 구조

## 7. 상용 제품 모듈

```text
ONSURE 스튜디오      사용자 프로젝트 등록·검증 실행·결과 탐색
ONSURE 검증 핵심부   정적·동적·정책·보안 검증 엔진
ONSURE 대상 SDK      언어·프레임워크·제품 어댑터 개발 계약
ONSURE 시험 연구실   시험 데이터 생성·버전·실패 등록소 관리
ONSURE 하네스        격리 실행·관찰·장애 주입·재현
ONSURE 오라클        기대 결과·정책·허용 오차 판정
ONSURE 개선기        근본원인 기반 개선안·승인형 패치
ONSURE 보고기        일반·기술·감사 보고서 생성
ONSURE 재검증기      수정 후 전체 재검증·회귀 잠금
ONSURE 증적 보관소   영수증·잠금·대장·최종 보고서 보존
```

## 8. 제품 불변조건

- 특정 검증 대상이 ONSURE 최종 판정 권위가 될 수 없다.
- 외부 제품 구성요소가 없어도 ONSURE 핵심 체계가 실행되어야 한다.
- 내장 에이전트·모듈은 독립 재검증 가능한 영수증을 내보내야 한다.
- 실행하지 않은 검사는 `PASS`가 될 수 없다.
- 보고서의 모든 중대한 결론은 증적에 연결되어야 한다.
- 개선 후 동일 시험 데이터와 변형 시험 데이터로 재검증해야 한다.
- 대상 어댑터 제거가 핵심 체계의 다른 대상 검증을 손상시키면 안 된다.

## 9. 단계별 제품화

```text
1단계  ONSURE 독립 범용 핵심 체계 강화
2단계  범용 대상 SDK와 보고·개선 사용자 경험 완성
3단계  중립 Java·Python·Node 실제 프로그램 전체 검증
4단계  OpenAPI·PostgreSQL·복합 서비스 검증 확장
5단계  대상 환경용 ONSURE 에이전트·모듈 선택 이식
6단계  추가 언어·프레임워크·다제품 대상 시장 확장
```

ONSURE의 제품 기준선은 1단계에서 독립적으로 성립해야 하며, 외부 제품 연계 없이
판매·배포·운영 가능한 구조를 유지한다.
