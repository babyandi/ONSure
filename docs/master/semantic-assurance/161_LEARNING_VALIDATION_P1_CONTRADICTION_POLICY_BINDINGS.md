# 161 Learning/Validation P1 Contradiction Policy Bindings

Status: `NORMATIVE_REFINEMENT / DESIGN_ONLY / NON_FINAL / CLAUDE_PROPOSED_PENDING_HUMAN_CONFIRMATION`
Scope: the 4 P1 contradiction classes named (but not enumerated) by 159 SS2 / 160 step 2 ("Cross-capability review identified 11 P0 and 4 P1 contradiction classes... 4 P1 remain review pending"). `contracts/learning-validation-95-contradiction-summary.candidate.v1.json` records `p1: 4` and 15 total `CR-LV-*` ids (001-015) but the original cross-capability review's own P1 content was never materialized into a document -- only the count survived. This document is Claude's own derivation of 4 real, textually-grounded P1 classes from the FR-LEARN-001~095 corpus, disjoint from 158's 11 P0 classes, proposed for human design-authority confirmation rather than asserted as the original review's exact list (which is not recoverable from anything currently in the repository).

이 문서는 158과 동일한 원칙을 따른다: 서로 정당한 요구가 동시에 적용될 때 precedence와 fail-closed 결과를 고정한다. 해결은 한 요구를 삭제하는 방식이 아니라 scope, authority, currentness, evidence minimization, HOLD semantics로 결합한다. P1은 P0과 달리 모든 개별 학습 결정을 즉시 차단하지는 않지만, 방치하면 P0으로 악화되거나 감사·규제 대응에서 실패하는 실질적 설계 긴장이다.

1. **Federated Aggregation Mechanism vs Tenant Isolation** (FR-LEARN-053 Federated Learning/Aggregation Governance vs FR-COM-002 Tenant 격리, FR-LEARN-046 Cross-Tenant Transfer Risk): 158 CLASS 4는 "개별 tenant 파생자산의 상위 scope 승격"에 대한 lineage/consent 요건이다. Federated aggregation은 승격 이벤트 없이도 여러 tenant의 신호를 동시에 집계하는 별개의 메커니즘이며, 집계 결과 자체가 (예: outlier tenant의 gradient 특성처럼) 개별 tenant 정보를 구조적으로 누출할 수 있다. Precedence: 최소 cohort 크기 미달 또는 outlier-dominant 집계는 REJECTED로 fail-closed하고, 매 aggregation round는 참여 tenant의 명시적 opt-in을 요구하며 자산 promotion 동의로 대체되지 않는다. 집계 결과에 개별 tenant를 역추적 가능하게 하는 diagnostic은 evaluator-only로 최소화한다.

2. **Reviewer/Evaluator Diversity Requirement vs Qualified-Reviewer Scarcity** (FR-LEARN-061 Reviewer Collusion/Consensus Bias, FR-LEARN-062 Evaluator Capture/Authority Concentration, FR-LEARN-093 External Evaluation/Red-team Independence): 위 세 요구는 모두 review/evaluation 주체의 다양성·독립성을 요구하지만, 고도로 전문화된 도메인(예: 금융권 AI assurance)에서는 자격을 갖춘 reviewer pool 자체가 작아 구조적으로 중첩이 불가피할 수 있다. Precedence: 가용 pool이 다양성 요건을 충족하지 못하면 요건을 조용히 완화하지 않는다 -- 해당 결정에는 `REDUCED_INDEPENDENCE_DISCLOSED` 플래그와 실제 중첩 사유를 명시하고, 고위험 결정(FR-LEARN-093 범위)은 외부 reviewer 추가 확보 전까지 HOLD한다. Pool 부족 자체를 "완전 독립 확인됨"으로 표시하지 않는다.

3. **Decision Explanation Fidelity vs Sealed Challenge/Benchmark Secrecy** (FR-LEARN-094 Decision Explanation Fidelity vs FR-LEARN-033 Challenge Set Secrecy): 158 CLASS 3은 방법론/범위/결과/권위 수준의 투명성과 sealed fixture 비공개를 구분한다. 그러나 FR-LEARN-094는 "실제 사용된 evidence/rule/oracle/policy 경로"에서 설명을 생성하도록 요구하며, 그 결정이 sealed Challenge Set에 대한 평가를 근거로 하는 경우 완전히 충실한 설명이 sealed fixture 내용을 노출할 위험이 있다 -- 개별 결정 설명 수준의 더 좁고 구체적인 긴장이다. Precedence: 설명은 결정에 실제로 사용된 evidence/rule/oracle/policy 식별자와 판단 근거를 충실히 반영하되, sealed fixture의 원문·정답을 그대로 재현하지 않는다 -- 참조는 redacted/abstracted digest 형태로 대체하고, 원문이 반드시 필요한 audit 상황은 evaluator-only 채널로 분리한다.

4. **Emergency Global Revocation Speed vs Data Residency/Air-gapped Isolation** (FR-LEARN-067 Emergency Global Revocation Propagation vs FR-LEARN-054 Data Residency/Cross-region Learning, FR-LEARN-068 Offline/Air-gapped Learning Synchronization): 긴급 revocation은 즉각적인 전역 전파를 요구하지만, data residency/주권 규제는 특정 payload의 국경 간 전송에 사전 통제를 요구할 수 있고 air-gapped 환경은 정의상 실시간 신호를 받을 수 없다. Precedence: 이 긴장은 사고 발생 시점에 즉흥적으로 풀지 않는다 -- (a) sovereignty-restricted region으로의 긴급 revocation 전송에 대한 법적 근거는 사전에 확보해 authority_refs로 결속하고, (b) air-gapped 환경은 실시간 currentness를 주장하지 않는 대신 명시적 `PROPAGATION_LAG_DISCLOSED` SLA(예: 다음 동기화 window까지 STALE 표시)를 유지한다. "이미 전파했다"고 자산의 currentness를 사전 확보 없이 가정하지 않는다.

모든 binding은 negative fixture가 필요하며 실제 runtime PASS는 Claude 구현/검증 단계에서만 가능하다. 이 문서 자체는 human design authority의 최종 확인 전까지 `DESIGN_ONLY / NON_FINAL`이며 Global Design/Implementation Lock에 대해 `P0_CONTRADICTIONS_DESIGN_RESOLVED_CANDIDATE`와 동일한 방식으로 `P1_CONTRADICTIONS_DESIGN_PROPOSED_CANDIDATE`로만 취급한다.
