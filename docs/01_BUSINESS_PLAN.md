# ONSURE 사업계획서

## 1. 사업 개요

ONSURE는 AI 프로그램을 자동 학습하고, 실제 수행 결과를 반복 검증하며, 발견된 결함과 부족한 부분을 자동 보완 개발하는 독립형 상용 제품입니다.

기존 정적 분석이나 테스트 자동화 제품이 정해진 규칙으로 오류를 찾는 데 집중한다면, ONSURE는 대상 AI 프로그램의 목적·구조·행동·실패 이력을 먼저 학습한 뒤 프로그램별 검증 기준과 개선 루프를 생성합니다.

## 2. 문제 인식

AI 코딩과 생성형 AI 응용프로그램이 빠르게 확산되면서 개발 속도는 높아졌지만 다음 문제가 커지고 있습니다.

- 개발자가 생성된 코드와 AI 동작을 충분히 이해하지 못함
- 코드 테스트만으로 프롬프트·RAG·도구·모델 변경을 검증하기 어려움
- 동일 입력에도 결과가 달라지는 행동 변동성이 존재함
- 보안·개인정보·권한·정책 위반이 실행 시점에 발생함
- 수정 후 실제 품질이 좋아졌는지 비교할 체계가 부족함
- 장애와 수정 경험이 조직의 재사용 가능한 자산으로 남지 않음

## 3. 제품 해법

```text
대상 등록
→ 프로그램·행동 학습
→ 기준선·시험 생성
→ 반복 실행 검증
→ 결함·누락·원인 진단
→ 자동 보완 개발
→ 수정 전후 비교
→ 개선 입증
→ 학습·실패·개선 경험 축적
```

ONSURE는 코드뿐 아니라 프롬프트, RAG, 모델 설정, 도구 계약, 테스트, 실행 로그와 정책을 하나의 AI 프로그램으로 묶어 관리합니다.

## 4. 핵심 제품 기능

### 4.1 자동 학습

- 저장소, 문서, 구성과 실행환경 분석
- 프로그램 목적·구조·인터페이스 재구성
- 정상·실패 행동 패턴 학습
- 변경·장애·수정 이력 축적
- 프로그램별 Program Model과 Behavior Model 생성

### 4.2 자동 검증

- 정상·경계·실패·적대 시나리오 생성
- 기능·정확성·일관성 검증
- 보안·개인정보·권한·정책 검증
- 프롬프트·RAG·도구·모델 변경 회귀검증
- 실행 가능한 실패 재현과 근본원인 분석

### 4.3 자동 보완 개발

- 코드 오류와 예외 처리 보완
- 프롬프트와 Tool Contract 개선
- RAG 데이터·검색·근거 연결 보완
- 누락 테스트와 회귀 Fixture 생성
- 설정·의존성·성능 문제 개선
- 브랜치·커밋·패치·PR 생성

### 4.4 개선 효과 입증

- 수정 전후 정확도·실패율·정책 위반률 비교
- 기존 정상 기능 회귀 여부 확인
- 실행 환경과 입력·출력·판정 근거 보존
- 개선 성공, 효과 없음, 회귀 발생을 구분 판정

## 5. 차별성

### 범용 코딩 에이전트와의 차이

범용 코딩 에이전트는 사용자의 요청을 받아 기능을 작성합니다. ONSURE의 보완 개발은 프로그램 학습과 실행 검증으로 확인된 문제에서 시작합니다.

### 정적 분석·보안 검사와의 차이

정해진 규칙만 적용하지 않고 프로그램별 목적·행동·실패 특성을 학습하여 검증 범위를 확장합니다.

### 테스트 자동화와의 차이

주어진 테스트 실행에 그치지 않고 테스트 부족을 탐지하고 필요한 정상·실패·적대 시나리오를 생성합니다.

### 평가 도구와의 차이

점수 산출로 끝나지 않고 원인 분석, 보완 개발, 재검증과 개선 효과 증명까지 폐쇄 루프로 수행합니다.

## 6. 목표 고객

- AI 코딩으로 제품을 개발한 개인·스타트업
- 자체 AI Agent·RAG 서비스를 개발한 기업
- 외주 AI 프로그램을 납품받아 검수해야 하는 조직
- 금융·공공·의료 등 신뢰성과 통제가 중요한 기관
- AI 솔루션을 반복 납품하는 개발사와 SI 기업
- 다수의 AI 프로그램을 운영하는 품질·보안·감사 조직

## 7. 제공 형태

- ONSURE Developer: 단일 프로젝트, IDE·CLI 중심
- ONSURE Team: 팀 저장소, 협업, PR·정책·이력 관리
- ONSURE Enterprise: 사내 설치, 다중 프로젝트, 권한·감사·비공개 시험
- ONSURE Assessment: 기간형 진단·보완·검증 서비스
- Embedded Edition: 향후 타 제품에 내장 가능한 라이선스

ORUDA 내장 형태는 향후 Embedded Edition의 한 사례일 뿐이며, ONSURE의 기본 판매 모델은 Standalone입니다.

## 8. 수익 모델

- 사용자·프로젝트·실행량 기반 구독
- 온프레미스 연간 라이선스
- 초기 설치·정책·검증팩 구성 비용
- 산업별 검증팩과 고급 시나리오팩
- 진단·보완·재검증 전문 서비스
- OEM·Embedded 라이선스

## 9. 시장 진입 전략

### 1단계: AI 코딩 결과 검증

일반 사용자와 소규모 개발팀이 만든 AI 프로그램을 빠르게 진단하고 패치와 보고서를 제공하여 초기 사례를 확보합니다.

### 2단계: AI Agent·RAG 품질 개선

코드 검증을 넘어 프롬프트·RAG·도구·모델 행동의 학습과 회귀검증을 제공해 차별화를 강화합니다.

### 3단계: 기업용 지속 개선

다중 프로젝트의 실패·개선 경험을 안전하게 축적하고 반복 검증·보완하는 기업용 플랫폼으로 확장합니다.

## 10. MVP

MVP는 다음 흐름을 실제로 완결해야 합니다.

```text
Git 저장소 등록
→ 코드·프롬프트·테스트 학습
→ Program Profile 생성
→ 결함·테스트 누락 탐지
→ 정상·경계·적대 시나리오 실행
→ 최소 1건 자동 보완
→ 전체 회귀검증
→ 수정 전후 개선 비교
→ Draft PR과 검증 보고서 생성
```

MVP에서 제외할 항목은 전사 지식 학습, 대규모 모델 훈련, 자유로운 신규 시스템 개발, 범용 프로젝트 관리와 운영 관제입니다.

## 11. 핵심 성과지표

- 등록 후 최초 Program Profile 생성 시간
- 기존 테스트가 놓친 유효 결함 발견률
- 자동 생성 시나리오의 재현 성공률
- 자동 보완 후 검증 통과율
- 수정 후 회귀 발생률
- 사람 검토 후 채택되는 패치 비율
- 동일 실패 유형 재발 탐지 시간 단축률
- 고객별 검증 준비 시간과 비용 절감률

## 12. 주요 위험과 통제

- 잘못된 자동 수정: 위험도 기반 권한과 롤백 적용
- 자기검증 편향: 보완 경로와 최종 판정 경로 분리
- 학습 데이터 오염: 출처·버전·권한·해시 관리
- 고객 정보 유출: 프로젝트 기억과 범용 패턴 분리
- 기준선 오류: 추론 기준은 임시 상태로 두고 승인 후 승격
- 범위 팽창: 등록된 AI 프로그램 개선과 직접 관련된 기능으로 제한

## 13. 최종 사업 메시지

> ONSURE는 AI 프로그램을 검사하는 도구가 아니라, 프로그램을 먼저 학습하고 실제 실패를 통해 스스로 개선하며 그 효과를 증명하는 독립형 AI 품질 개선 제품입니다.
